## Integrating Email Verification Protocol

To implement an instant, cryptographic email verification flow on your website, you can integrate the experimental **Email Verification Protocol (EVP)**.

### Implementation Guide

To request an Email Verification Token (EVT), you need to configure your registration/sign-in form with specific HTML attributes that the browser recognizes:

- **Email input field:** Set `type="email"` and `autocomplete="email"`.
- **Hidden token field:** Set `type="hidden"` and `autocomplete="email-verification-token"`. The browser will automatically inject the base64-encoded token into this input upon autofill.
- **Session nonce:** Set the `nonce` attribute on the hidden token field to a cryptographically secure, session-bound value generated by your server.

Here is a basic HTML structure:

```html
<form id="registration-form">
  <input type="email" autocomplete="email" required />
  <input
    type="hidden"
    autocomplete="email-verification-token"
    nonce="SERVER_GENERATED_NONCE"
  />
  <button type="submit">Register</button>
</form>
```

### Best practices & verification checklist

When implementing EVP, follow these security and integration best practices:

- **Robust fallback:** Always implement a traditional fallback mechanism (like sending a 6-digit OTP code or verification link) if the browser does not support EVP or fails to populate the token.
- **Server-side verification:** Never trust the email address sent in the standard email input. Always send the `email-verification-token` to your backend and cryptographically verify the token (verifying the signature, the issuer's authority over the email domain via DNS TXT records, and the session nonce binding).
- **Session-bound nonces:** Generate a unique, cryptographically strong nonce per session. Verify that the nonce contained in the Key Binding JWT (KB-JWT) matches the expected nonce for that user's session to prevent replay attacks.
- **Inspect using DevTools:** During local development, print the verification trace steps to the console to debug token decomposition, DNS delegation, and signature verification.
