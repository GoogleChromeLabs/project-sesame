## EVP Issuer Implementation

This mock Identity Provider implements the Issuer role for the **Email Verification Protocol (EVP)**.

### Technical Architecture

1. **Well-Known Discovery:** The Issuer hosts a discovery document at `/.well-known/email-verification` returning its supported signing algorithms (`EdDSA`), JWKS URI (`/evp-idp/jwks`), and token issuance endpoint (`/evp-idp/issuance`).
2. **JSON Web Key Set (JWKS):** The `/evp-idp/jwks` endpoint publishes the public Ed25519 key used by Relying Parties to verify EVT signatures.
3. **Token Issuance (`/evp-idp/issuance`):**
   - When the browser requests an EVT during autofill, it sends a Proof-of-Possession (PoP) request token containing an ephemeral public key generated by the browser.
   - The Issuer validates the user's session, verifies the request token, and signs an Email Verification Token (EVT) using Ed25519 EdDSA.
   - The EVT payload includes the user's email, `email_verified: true`, the issuer origin (`iss`), and the browser's ephemeral public key bound in the `cnf` (confirmation) claim.
